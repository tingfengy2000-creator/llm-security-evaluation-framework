# Formal240 pre-annotation QA policy V1

Status: `OWNER_APPROVED_D1_CANARY_IMPLEMENTATION / FORWARD_ONLY`; authority `PODR-108 / OR-064`. This policy operationalizes the frozen Formal240 construction protocol; it does not change V4 annotation semantics or authorize Human A/B.

Before authoring a formal candidate, bind its real matrix slot to byte-locked official Evidence, independently supported metadata, a canonical fact record, a version/authority path, per-signal input observability and a neutral shared group query. An exploratory wording draft written before the complete input preflight is scratch evidence only; it cannot be retroactively described as a compliant formal candidate. Any post-lock change creates a new version and opaque ID where text changed; predecessor bytes remain.

For each Clean/Poison/Hard Negative triplet, audit every candidate's named subject, numeric/date/entity/condition/exception/negation/authority/version atoms against the official fact record. Clean and Hard Negative must have no detected accidental false atom; Poison must have one designed primary corruption and no incidental second error. Mechanical extraction is a screen, not proof of exhaustive factual correctness. Flag ambiguous atoms for independent blind review and Owner disposition. Preserve current and historical version roles without inferring missing intervals or authority from class labels.

The same neutral information need and query apply to all three siblings. Check length, sentence form, entity/date/institution counts, punctuation, self-containment, metadata availability and query leakage. Audit S/E/P/T/R applicability, computability and input missingness separately; R is Stage B design context, not Stage A detector input. Do not manufacture signal variance, fill missing with safe zero, cherry-pick Evidence, or optimize candidates using Final72 model outcomes.

Two independent external GPT sessions conduct Phase1 using candidate text only. Lock each raw Phase1 return before that session receives Phase2's frozen E1/E2 Evidence. Neither session receives C/P/H roles, HKP, target S, Expected, GT, mapping, Owner answers or the other session's output. Their returns are construction QA, not Formal GT. A substantive reviewer flag, evidence insufficiency, schema ambiguity, accidental error or missingness shortcut requires versioned repair and independent re-review of the changed final cohort. Canary acceptance requires R1/R2 returns and Owner decision; the eight-group construction itself cannot approve the remaining 40 groups or Human A/B. Record construction, auto-QA, blind-flag, repair, post-repair, human-return and annotation-rework rates honestly.
