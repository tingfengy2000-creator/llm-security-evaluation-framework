## 3. 研究方向与论文定位（Owner 2026-11-12 同意）

场景：中文法规、政策类 RAG。同一制度存在合法的新旧版本，新修订内容往往不在模型训练知识里；攻击者向知识库写入不含指令的“正常文档”式错误事实（错误数值、旧版本、伪造“最新修订”）。

- 主贡献：两类主流防御在该场景下的失效机理。（1）RAGDefender 中文迁移失败并大量误删；（2）LLM 核验的裁决来自模型自身知识，对模型不知道的事实会站在多数一边、删掉正确证据，把生成器原本的拒答变成被骗作答。
- 次贡献：知识感知门控 KAG，一个有原则的缓解方法——模型知道才允许核验删除，不知道就不删并标记冲突。KAG 不发起新检索；“转可信来源”只是下游选项，不作为贡献。
- 不把 KAG 包装成主角；不宣称“轻量”（每查询约 8 次小调用），可写“低成本、按需触发”。
- 需引用并区分：自适应检索（Mallen 等 2023）、Sufficient Context（ICLR 2025）、Astute RAG、知识冲突研究。区别在用途：它们决定是否检索以提高准确率，本文决定防御能否删除证据。

研究问题：RQ1 RAGDefender 在中文版本敏感场景是否有效、为何失效；RQ2 防御是否在回答层诱发攻击；RQ3 LLM 核验是否依赖模型参数知识；RQ4 KAG 能否在不牺牲安全的前提下保留核验的收益。

## 4. 方法与对比臂

管线：查询 → 检索 TopK=5 → 防御层 → 生成器（qwen3.7-plus-2026-05-26，temperature 0，非思考，百炼北京）→ 回答。只替换防御层。

- NONE：不防御。
- RD_B2：RAGDefender v0.2.0（提交 ba2a17e）+ paraphrase-multilingual-MiniLM-L12-v2。RD_ZH：字二元组分词版。
- QWEN_VERIFY（QV）：单次 Qwen 调用判断各片段可信与否并删除。
- KAG：闭卷探针（不给片段）两次 + 各片段答案值抽取（QAG 抽取器，准确率 175/179）。闭卷值一致且与某片段值相符 → KNOWS，采用 QV 掩码；否则 → CONFLICT_UNRESOLVED，保留全部 5 段。
  - v0：闭卷原话直接与片段值做字符串比较（已证实失配严重）。
  - V1：闭卷回答走同一抽取器；第二探针换 JSON 模板；最小归一扩充；数值相同且第二探针给出单位时补齐首轮缺失单位。
  - V1T：V1 + 时效门（任一片段出现 2025 年及以后的修订/施行时点 → 强制 CONFLICT）。
  - 按需触发：片段归一值少于 2 个不同值 → NO_CONFLICT，直接放行，不做闭卷比较与核验。
  - +TAG（Owner 提议）：仅对 CONFLICT 世界，在生成提示中中性地列出互相矛盾的值与证据 ID，允许输出 CONFLICT_DISCLOSED（列出候选值，建议以官方文本为准）。
- 设计原则：攻击者可控的信号只能降低信任（P0 单调性）；KAG 的错误偏向安全侧（宁可少删、多拒答）。

## 8. 一句话读懂核心发现

不防御时，生成器看到互相矛盾的证据几乎都拒答。加了 LLM 核验，冲突被“消掉”：模型知道的题答对了，模型不知道的题被骗了。核验把“不确定”变成了“确定的错”。KAG 的作用是只让核验在模型确实知道时动手。
