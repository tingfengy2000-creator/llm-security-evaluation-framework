# Stage 2 Mock API 与 Stage 3 真实 API

## 1. 两者不是替代关系

Mock API 用于控制变量，真实 API 用于观察真实行为。成熟企业会同时保留：

- Mock 保障接口和测试框架的确定性。
- 真实模型扫描保障安全结论与实际部署相关。

## 2. Stage 2 Mock API 的价值

Stage 2 可以人为规定：

- vulnerable 必须回显。
- guarded 遇到关键词必须拒绝。
- API 响应格式固定。
- 没有网络、额度、服务升级和供应商故障。

因此它适合验证：

1. `/v1/chat/completions` 请求格式。
2. garak Generator 是否正确取回输出。
3. Probe 和 Detector 是否按预期配合。
4. 正反对照能否产生不同结果。
5. JSONL、HTML、日志和聚合脚本是否正确。

## 3. Mock 为什么不能代表真实模型安全

Mock 没有真实 LLM 的：

- 自然语言理解。
- 指令优先级和对齐行为。
- 随机生成。
- 同义改写和多轮上下文。
- 模型供应商的隐藏系统策略。
- 真实解码、推理和拒绝能力。

Stage 2 的 100% ASR 说明回显器满足 Detector 的命中条件，不代表某个真实模型的 ASR。

## 4. Stage 3 真实 API 的价值

Stage 3 能观察：

- 模型是否理解并服从攻击。
- 模型是否拒绝或安全改写。
- 编码内容是否会被模型解码。
- 相同 Probe 在真实生成中的误报和漏报。
- 限流、重试和模型版本变化等生产问题。

它更适合面试展示，因为项目不止“模拟了一个接口”，还完成了真实模型接入、控额、证据保留和
结果边界分析。

## 5. 关键差异

| 维度 | Mock API | Groq 真实 API |
| --- | --- | --- |
| 后端 | Python 规则 | 真实 LLM |
| 可控性 | 高 | 较低 |
| 可重复性 | 高 | 受采样和服务变化影响 |
| 网络与鉴权 | 可省略 | 必须处理 |
| 速率限制 | 无 | 有 |
| 成本 | 近似为零 | 受额度/计费约束 |
| 安全结论 | 流程级 | 模型样本级 |
| 调试价值 | 高 | 依赖 Mock 基线定位 |

## 6. 为什么真实结果可能“更乱”

真实模型可能在同一攻击下：

- 第一次拒绝，第二次部分服从。
- 输出攻击目标的解释性引用。
- 生成近义句，字符串 Detector 没命中。
- 因输出长度限制而截断。
- 因 429 没有生成有效输出。

所以真实结果需要结合 Attempt 原文和运行日志，而不只是看一行 PASS/FAIL。

## 7. 企业里的递进流程

```mermaid
flowchart LR
    A["单元测试 / Mock"] --> B["集成测试 / Staging Model"]
    B --> C["真实模型小样本 Smoke Test"]
    C --> D["完整安全回归"]
    D --> E["人工红队与业务验收"]
    E --> F["上线监控与事件复盘"]
```

本项目的 Stage 1、2、3 对应前三步的最小实现。

## 8. 面试怎么讲

“我没有直接把扫描失败都归因于模型。我先用 Repeat Generator 验证 Detector，再做
vulnerable/guarded Mock 对照验证 API 集成，最后只替换连接参数接入 Groq 真实模型。这样我能
把框架错误、接口错误和模型风险分开，并保留 JSONL 证据进行复盘。”

## 9. 初学者误区

1. Mock PASS 不证明真实模型 PASS。
2. 真实 API 更真实，但并不天然更适合调试。
3. OpenAI-compatible 解决接口迁移，不解决模型行为一致性。
4. 真实模型的一次运行不是长期安全认证。
