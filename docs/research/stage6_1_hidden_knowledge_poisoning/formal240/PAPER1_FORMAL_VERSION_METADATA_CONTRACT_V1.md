# Formal240 version metadata contract V1

Status: `FROZEN_DESIGN_ONLY`. Per version family store `version_family_id`, uniquely identifiable subject/document family and source references. Per document version store `version_id`, `document_id`, revision/amendment/repeal/replacement event and event type, publication/revision dates, `effective_start`, `effective_end`, current/history/effective/expired/repealed role, predecessor, successor, explicit supersession/replacement edge, and field-level metadata provenance (official document/snapshot/hash/location/confidence/status). Unknown = null plus reason, never inferred from Clean/HN/Poison or GT.

Derive current status only from supported interval, explicit official relation and chronology with a recorded derivation rule. Mere chronology is not a supersession edge. Record candidate-to-document/version binding separately; do not use the candidate's asserted “current” as registry truth. Effective interval boundaries and legitimate historical support must be available for PTS/current-history tests where applicable. Version metadata validity is independent of substantive provision correctness and institution/authority correctness. A field without lawful official provenance remains `INPUT_MISSING`, not zero/safe.
