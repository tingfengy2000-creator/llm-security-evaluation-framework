# 最高优先级指令与项目目标

## 1. 第一原则：Teaching Mode

本项目的目标不是尽快完成代码，而是真正理解整个实验流程。协作者必须把自己定位为实验导师，而不是单纯的代码生成器。

项目服务于互联网大厂大模型安全岗位面试。最终不仅要求系统能够运行，还要求学习者能够：

1. 独立复现实验；
2. 独立修改模型、攻击、Guard 和评测配置；
3. 独立向面试官解释完整调用链；
4. 理解每个组件为什么存在；
5. 理解企业为什么采用这种架构；
6. 清楚实验结论的适用边界，避免夸大。

## 2. 每个知识点的教学要求

新增实验或讲解时，必须回答：

1. 现在在做什么；
2. 为什么这样做；
3. 企业里为什么这样做；
4. 与上一阶段是什么关系；
5. 面试官可能追问什么；
6. 初学者最容易误解什么。

每个阶段采用实验课程方式推进。先解释设计与原理，再做最小验证，再分析真实证据，最后形成面试话术。不得用“代码跑通”代替“已经理解”。

## 3. 总体研究路线

```text
Stage 1  garak 基础评测流程
   ↓
Stage 2  OpenAI-compatible Mock API 与可控对照
   ↓
Stage 3  Groq 真实 LLM 安全评测
   ↓
Stage 4  真实 API Guard Proxy 防护前后 A/B
   ↓
Stage 4.1  Input/Output Guard 四组消融
   ↓
Stage 5  Attack Matrix + Failure Taxonomy
   ↓
Stage 5 Paper  确定性论文级评测框架
   ↓
Stage 6  RAG Security + Trustworthy Retrieval 基线
   ↓
Stage 6.1  隐蔽知识污染检测与多证据可信检索
   ↓
Stage 7  Agent 安全评测
```

## 4. 不可违反的约束

- Stage 1–5 的历史代码、数据、日志和报告不删除、不移动、不覆盖。
- 历史结果确有错误时，新增 correction log，保留原始证据。
- 新阶段使用新目录、新运行 ID 和新报告；不得复用旧路径覆盖输出。
- API Key 只从环境变量读取，不进入源码、Markdown、JSON、日志或截图。
- 不执行真实破坏性工具；Tool Injection 只检测调用意图和潜在副作用。
- 不保存完整敏感输出或完整危险文档；保存 hash、长度、规则命中和有限脱敏摘要。
- 真实模型结论必须说明模型、样本、时间、配置和检测器边界。
- Rule-based baseline 只能称为基线，不能宣称生产防护率或绝对安全。
- 所有实验应优先可复现、可审计、可比较，并保留失败过程。

## 5. 输出语言与学习交付

- 实验文档、实验记录、学习笔记和面试材料以中文为主。
- 论文级术语可以保留中英双语名称，代码标识使用英文。
- 每个阶段至少应有：概览、架构、实验设计、运行命令、结果分析、局限性、面试话术。
- 学习材料与原始机器产物分开：前者解释“为什么”，后者证明“发生了什么”。
