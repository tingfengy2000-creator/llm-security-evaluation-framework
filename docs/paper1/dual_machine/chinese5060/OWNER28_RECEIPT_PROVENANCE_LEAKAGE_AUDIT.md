# Owner28｜来源收据的信息泄漏审计

Owner27 的 T1 使用 **LOCAL_SYNTHETIC_RECEIPT**。本地收据确实绑定自写段落的 UID 和字节，但由 DEV 造数者按预先知道的语义与版本赋予。它携带类似 Oracle 的真值侧信息。T1 三臂比较仍共享同一信息预算，T1 相对 T0 的差异不能直接外推为可部署方法收益。

依据是 [Owner27 封存 Manifest](OWNER27_OFFLINE_FASTTRACK_RUN_MANIFEST.json)、[只读复算](OWNER28_DEV_FAILURE_ATLAS.md)、归档的造数代码和执行代码。造数代码 SHA256 为 4145055a77d408307e341ddbd7ce4accface25e79d713ed5fa4839739fb4fa7c，执行守卫 SHA256 为 5bc0b2c7712c494802c5e51dfad98f8468f6d1ca032cc3ad349c5b1434b68768。收据生成见前者 162–167 行。

| 字段或信号 | 封存代码的来源与消费 | 部署解释 |
| --- | --- | --- |
| 收据存在、document、content_sha256 | 造数者先确定候选语义，按 admitted 路径给部分自写文档发收据。守卫核 UID 与该段所属文档字节哈希。 | 本地完整性绑定可核。存在与否已经高度关联正常角色。相同哈希不能证明真实签发者或独立审核。 |
| normalized_value_sha256 | 直接哈希造数卡的真值摘要。异范围版本有意沿用当前版本的相同规范值。守卫用等值测试冲突。 | 哈希保留同值、异值关系。守卫未从原始文档独立提取并核验该值。 |
| scope、fact、lineage | 造数者给每条已知文档指定范围、事实与谱系。查询范围来自另一个视图。简单规则比较同 scope，联合臂先找同范围锚，再扩到同事实谱系的有效范围。 | 这些绑定有现实来源可核，但本批来自同一开发方，免掉了歧义、错绑与独立签发的成本。 |
| version、start/end、source_uri | 造数者把预检登记的旧或新版本映射到自写段，填官方链接和区间。守卫按左闭右开判有效期。version 与 URI 在该决策函数中不用于验签或联网核验。 | 链接和有效日期可以是真实元数据。代理文本的正确版本归属仍由造数者给定。 |
| 角色文件 | 评价角色单列在 evaluator-only，历史预测先封存后读角色。执行掩码没有读该文件。 | 未观察到评价角色文件直传。当前发现的是通过赋证、字段和覆盖差异引入的间接真值信息。 |

| --- | ---: | ---: |

主 TopK 有 55/160 个收据绑定，涉及 30/32 世界。Clean 有 33/63 段未绑定，HN 有 8/33 段未绑定。全 40 世界有 78/440 个绑定。覆盖差异在选择上把造数者认定的有效来源与潜在错误分开，因此零错误放回只说明这种受控注册策略的行为。三条 T1 对相同 32 个主世界收到相同收据视图，简单和联合各恢复 25 段 Clean，联合只比简单多恢复 2 段异范围 HN。

去 scope 臂把所有有效绑定都纳入锚候选。S3 和 S7 被恢复的异范围段与同范围锚共享事实谱系和规范值哈希，去 scope 仍可恢复这 2 段。联合与去 scope 在 32/32 主世界掩码相同，当前设计无法识别 scope 的独立效应。该消融也未检验一个真值摘要被不同签发者独立生成的可复现性。

**REAL_SIGNED_RECEIPT** 需要独立签发者和可验证签名，明确密钥信任链、覆盖的文档字节、版本、有效区间、范围、授权和撤销，并证明字段的产生不依赖评价角色。本批符合该定义的收据为 **0**。官方 URL、Git 哈希与本地收据是不同证据。Owner28 四臂采用 T0，输入模式拒绝收据、规范值和评价字段。
