### 无答案查询与隔离

1. 策划者生成业务情景卡，仅提供对象、地区/人群、事件时点与所问谓词。独立出题者在看不到正文差分、目标答案、攻击文本、排序、方法和结果的条件下自然写问句。禁用答案字串、法规条号暗示、攻击角色和引导语。明确区分事件时点与网页抓取日期；优先使用明确时点的同题跨期配对。
2. 两名评价员独立核对条款、版号、日期、范围、例外和字符/UTF-8 证据 span，分歧交第三人裁决。先确认资料权利，再以新私有路径冻结 `registry/seal`、`query/seal`、`evaluation/seal`。只有可核凭据，不从目录名或自称网页推断授权。
3. 出题、攻击制作、检索、防御与评价分视图。攻击者可修改低信任语料内的值、scope 和版号，可复制或改写传播，不可修改 query、采集登记、可信收据、索引参数和排序。检索/防御的白名单只有不透明世界 ID、query、有序 chunks/rank/原文字节哈希和获批权限层的元数据。有效 span 和角色、变异目标、映射、未公开裁决各自存放。世界语料中不混入另一互斥候选变体；文件名、UID、顺序不能编码角色。
4. 对批准的官方原文，采集记录至少绑定发布者权限、最终官方 URI、抓取时间、原始与规范化 SHA256、文档版本、有效区间与范围、原文定位。收据在独立可信登记中绑定文件和 chunk，出处自称及镜像一律不赋权。证据登记不携带问题答案。来源收据证明采集和来源绑定，真实签发者失陷时仍需记录残余风险。
5. 每世界固定独立索引和背景集合；拟沿用 CPU、固定缓存 multilingual-MiniLM revision `16e5344fbfc7dfbbbe0019d30cec21e2940cb4e1`、96 token 窗/16 重叠、Chroma 1.5.9 cosine、TopK=5 与既有 tie-break。审批后核依赖、collection、tokenizer、语料成员 hash、输入和读回重放，冻结 TopK 顺序、query 和内容，再一次性运行 EVAL。防御器只输出原 rank 子序列。禁止换文、回填或逐臂重检索。完整预测哈希和输入绑定封存后，评价进程才读取角色和裁决。
