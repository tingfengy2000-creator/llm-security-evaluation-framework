# VACE-Lite V0.2候选方法规格：同范围、同版本的轻量命题—证据核验

2026-10-28；PODR-147 / OR-101 / REL-2026-0116。
状态：`CANDIDATE_SPEC / VACE_LITE_V02_OWNER_REVIEW_REQUIRED`，不是已实现、已验收方法。

## 摘要与边界

问题：识别中文RAG知识库派生文本中数值、条件、版本和来源角色篡改，同时保留正常知识与合法历史版本。
本轮只完成A0开发诊断和本规格，不运行VACE、LLM/NLI或新检测训练。
第一版基础单元是短候选命题，非真实长文档。当前120条字数范围见本轮审计；
“把污染句嵌入固定正常长段落”登记为后续独立条件，本轮不执行，不宣称文档级检测。
不要求极端隐蔽攻击；保留既有HKP1–4、S1–3、Clean/Poison/HN、人工原答和冻结Evidence。
V0.1全文未定位；V0.2依据Owner本轮明确六槽位要求和字节锁定外部意见新增，原稿不覆盖。

## 1. 第一版只有六个事实槽位

| 槽位 | 内容 | 判断时的必要约束 |
| --- | --- | --- |
| subject | 主体、规范对象、文件/条款身份 | 同名不同对象不能合并；不明确指代不得自行补前件 |
| predicate | 谓词及事实关系、比较对象与方向 | “提高/降低”“通过/公布”是不同关系；不能只对词袋 |
| value_unit | 数值、阈值、区间、单位及所修饰实体 | 数字须绑定谓词/主体；保留“以上/超过”等端点 |
| scope | 条件、例外、量词、肯否极性及作用域 | 不能把不同条件的允许/禁止当内部矛盾；不自动把未陈述量词补成“全部” |
| time_version | 时间锚点、版本身份、有效区间及关系 | 历史资格与当前适用分开；未知版本不因未收录就判其不存在 |
| source_role | host、页面发布者及通过/公布/制定/修订/转载机关的显式角色关系 | 不把gov域名、页面发布者、原制定机关自动等同 |

每槽位保存value、Candidate原文span及OBSERVED / NOT_STATED / NOT_APPLICABLE / UNRESOLVED。
这些是六槽位内的状态/出处，不扩成新事实字段。外部metadata另存来源/版本UID和证据span，不能从GT推断。
subject/predicate通常必需；数值/版本/机关主张是否出现先按Candidate本身判定。
NOT_APPLICABLE不等于安全或零风险；NOT_STATED与UNRESOLVED不得混同。

继承V4–V4.3的Candidate-only版本边界：普通“《甲办法》第X条规定Y”不自动产生版本主张。
具体数字错不自动使version错误，机关错不自动使version错误。Evidence页有日期/现行标识不能反向制造主张。
无显式版本主张的规范句若需当前适用判断，依据外部给定as_of及Registry建立适用域；
适用域不明时弃权，不更改人工Guide枚举或把“没写版本”当作版本错误。

## 2. 最小流程及可信边界

`Candidate → 六槽位提取 → 独立可信检索 → 同范围/同版本对齐 → SUPPORT/CONTRADICT/INSUFFICIENT → 分流`

1. 提取器只读Candidate原文，输出六槽位与未解析状态；不读C/P/H、S、HKP、人工E1/E2映射、Expected或GT。
2. 查询由Candidate/槽位确定性生成；复用冻结统一官方语料、固定Top5与Registry，不为单题挑证据。
3. 对齐器按文档/版本家族分区，核对主体、关系、scope、time，再比较值/方向/机关角色。
4. 每条可验证子命题保留Candidate span ↔ Evidence UID/span、版本边及reason code。
5. 确定性聚合所有相关同域证据；不选最能“判毒”的一份，不因任意旧版冲突就判Poison。

第一版不采用GNN、端到端大模型、复杂融合或长上下文；不用内部激活，不训练风险校准器。
已有S/E/P/T信号作为对照与可解释来源，不静默替换既有Feature Set；R仍是Stage B query-conditioned视角。
可信官方库覆盖有限，企业知识库有派生文本，因此必须报告命题可对齐覆盖率，不能假定全部可核验。

## 3. 可操作判决

| 判决 | 充分条件 | 不能据此判决的情形 |
| --- | --- | --- |
| SUPPORT | 全部适用且必要的核心槽位，在同主体/同范围/版本相容证据中有支持span，无未解决相反证据 | 仅语义相似、仅未发现错误、只找到相同数字 |
| CONTRADICT | 在相同主体、关系、scope及时间/版本适用域内，冻结证据明确支持相反事实；或文本内两个同域命题逻辑互斥 | 证据没提到、Registry没收录、不同历史版本不同、缺第二证据 |
| INSUFFICIENT | 任一必要槽位/身份/范围/版本关系未绑定，证据缺口或可靠性未解决 | 不得强制转换为Poison或Clean |

“全部必要槽位”不要求给不存在的数值/机关主张找证据；但未交代的必要对象或条件不能靠想象补齐。
独立内部冲突路径S1可不检索外证，但必须确认同主体/同时间/同scope，不能仅凭“既…也/同一”。
S2需要至少一份足以独立证伪的官方证据；实际阅读了E1+E2不等于最低需求S3。
S3需要各版本/多证据的可追溯关系和共同必要的证据链，不能以拼接文档数量代替联合核验。

聚合顺序：经证明的同域CONTRADICT→冲突风险；否则全部子命题SUPPORT→证据支持；
否则INSUFFICIENT→人工复核。先检查可信证据自身冲突/身份不明：若无法裁定，输出INSUFFICIENT而非挑一方判毒。
这是事实污染风险，不证明攻击者意图；标签仅由独立Evaluator评价。

## 4. 四类机制的可测目标

- HKP1：绑定subject/predicate/value_unit后比较，避免把同文档其他数字当反例。
- HKP2：显式条件/例外/量词/否定范围，检查必要条件被删除、扩大或替换，不因合法例外误报。
- HKP3：比较版本链/有效区间及历史资格，区分正确历史事实与错误当前绑定；不靠语言自然度。
- HKP4：比较机关—角色关系，不把采用机关、公布机关、修订机关和官方转载机构混为一谈。

## 5. 最小工程实现（尚未授权执行）

一个六槽位JSON schema、Candidate/Evidence两个独立适配器、确定性Top5检索接口、
基于字典/关系表的scope/version对齐器、三态判决器、可回溯reason codes与单元测试。
先做规则能可靠表达的命题，不能表达则INSUFFICIENT，不自动调用LLM补答案。
最小对照：A0/A/B1/L0及同证据VACE-Lite；Oracle仅作独立诊断。
验证版可做三个嵌套消融：基础槽位；+范围约束；+版本/机关角色约束，不能删除表现不好的条件。
不先训练新fusion；只有公平对照证明必要且Owner批准才扩大实现。

输出至少：verdict、reason codes、applicable slots、slot bindings、证据refs、version/authority冲突原因、review_required。
不把三态任意映射成0/0.5/1“校准概率”。未来连续风险须另冻结评分、阈值和abstention合同。
弃权不计检出TP；报告全体Poison Recall、覆盖率、弃权率及选择性性能，不能靠弃权删除难例。
