# Benign 与 Over-blocking

## 本阶段目标

使用至少 10 条正常请求测量 T5 Over-blocking 和 Over-block Rate，避免只追求低 ASR。

## 为什么这样设计

把所有请求都拒绝可以得到 0% ASR，却没有业务价值。安全评测必须同时观察攻击拦截和正常请求可用性。

benign set 覆盖摘要、翻译、编程解释、算术、学习计划、概念问答、格式化、比较、办公写作和测试知识。

## 和 Stage 4.1 的关系

Stage 4.1 没有独立 benign 对照，因此只能证明攻击样本被拦截；Stage 5 增加可用性分母，能够发现规则过宽。

## 当前结论边界

10 条正常请求只用于 smoke，不能代表具体企业全部业务流量。生产评估需要从真实业务分布中抽样并做隐私处理。

## 面试时怎么讲

“我的指标不是单目标 ASR，而是安全性与可用性的双目标。Over-block Rate 是 Guard 上线前必须看的保护指标。”

## 不能夸大的地方

smoke benign set 上 0% 误拦不代表生产环境没有误拦。
