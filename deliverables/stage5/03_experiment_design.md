# 实验设计与不变量

## 本阶段目标

在相同模型、seed、样本和渲染结果下运行四种 Guard Mode，并用 validators 判定实验是否有效。

## 为什么这样设计

关键不变量如下：

1. 同一 sample 的四模式 `prompt_hash` 必须一致。
2. output-only 必须关闭输入防护、开启输出防护、调用上游、不发生输入拦截，并记录原始输出 hash。
3. 每个 sample 必须具有四条完整记录。
4. 结果产物不得出现凭据标记。
5. 原始危险输出不持久化，只保存 hash、长度、命中规则和有限元数据。

默认 seed 为 42，并发为 1。真实 smoke 在样本组之间等待，以降低免费接口限流概率。

## 和 Stage 4.1 的关系

Stage 4.1 已验证四模式的基本字段；Stage 5 将这些约束做成自动 validator，任何缺模式、缺 hash 或 output-only 语义错误都会使 run 失效。

## 当前结论边界

相同 seed 不保证所有服务端模型严格确定，因此 raw output hash 差异作为观察项报告，不自动等价为攻击效果变化。

## 面试时怎么讲

“A/B 的核心不是两条命令，而是控制变量。我把 prompt parity、output-only 调用顺序和报告完整性写成机器可执行的不变量。”

## 不能夸大的地方

框架能提高可复现性，但无法消除服务端模型更新、采样实现和网络环境造成的波动。
